## Production blocker resolution

**First publication.** A valid, empty protected-ref Authority tree made `loadDelegatorTrust` throw `RUNTIME_AUTHORITY_NOT_FOUND`. `createAppUserSetupProvider.readCanonicalAuthorities` mapped that to unavailable trust, so shared Setup did not offer `authority.publish-trust`. That provider now maps this specific empty-tree result to zero records. The trust comparison returns `untrusted`, enabling first publication. Other errors still fail closed. The packed CLI test confirms a 503 tree read remains `unknown` and cannot publish; both CLI and browser confirm first PR creation and post-merge recheck.

**360px overflow.** The single-column `.layout` grid used a minimum content width, leaving a 369px document at a 360px viewport. The narrow breakpoint now lets its direct children shrink with `min-width: 0`. The actual packed console in Chromium passes the width and element-boundary assertions.

## Verification boundary

`pnpm run verify` was executed after the fixes. Its `test` task fails in Change CLI tests that expect a pre-Session command path while the current production command requires `INARI_SESSION_ID`; a representative failure is `src/change-cli.test.ts` expecting exit 0 and receiving exit 2 with `ADMISSION_SESSION_SELECTOR_REQUIRED`. The same targeted test fails on the exact base commit `b4b2d224c57e3b8342148970229ef247b6f4dc67` in an isolated worktree. This is outside the two authorized production fixes and remains a full-suite blocker; the #1122 focused certification checks are reported separately.
