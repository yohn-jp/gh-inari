# gh-inari 0.3.0

## Summary

The 0.3.0 release closes hardening gaps found across governance identity,
GitHub API response handling, transport output bounds, extension bootstrap,
and packaged-release verification. No supported command semantics change.

## Highlights

- Repository-governed mutations now bind to an immutable Git tree SHA
  captured when governance was compiled, not just the mutable branch ref,
  so a mutation can detect a stale governance generation.
- The bounded `gh` transport now enforces stdout/stderr byte limits per
  operation and surfaces a typed `GITHUB_OUTPUT_LIMIT_EXCEEDED` error
  instead of buffering unbounded output.
- GitHub PR responses reject a malformed or missing `draft` field instead
  of silently coercing it to `false`.
- Issue mutations read the target resource first and refuse to treat a
  pull request as an Issue artifact, failing closed with
  `GITHUB_RESOURCE_KIND_MISMATCH`.
- The `gh-inari` extension launcher's dependency bootstrap is now a
  one-shot re-exec: a broken packaged distribution or a still-missing
  runtime dependency after one bootstrap attempt fails closed instead of
  retrying indefinitely.
- CI now fails if the committed `dist/` output drifts from a clean build,
  and the package smoke test runs the checked-out extension and the
  packed tarball in fully isolated `gh` CLI state (`XDG_STATE_HOME`
  included) so neither can mutate the process owner's real `gh` state.

## Fixed

- Fixed governed mutations trusting a compiled contract whose repository
  tree had since changed underneath it.
- Fixed the `gh` transport buffering unbounded stdout/stderr from
  long-running or misbehaving `gh` invocations.
- Fixed PR response parsing accepting any non-`true` value for `draft` as
  `false` instead of rejecting a malformed field.
- Fixed Issue mutations silently overwriting a pull request's Issue Form
  content when the numbered resource was actually a pull request.
- Fixed the extension launcher being able to re-attempt dependency
  bootstrap indefinitely against a persistently broken install.
- Fixed the package smoke test's isolated `gh` CLI extension state
  leaking into the process owner's real `gh` state, and corrected an
  undefined `installDirectory` reference in its environment setup.

## Behavioral changes

- Contract provenance now requires a `treeSha` field; governance IR
  compiled before this release without that field is rejected.
- Issue mutation operations (`update`, etc.) now perform an additional
  read of the target Issue before mutating it.

## Upgrade instructions

Install the published package:

```bash
npm install --global gh-inari@0.3.0
```

Or install the extension directly from this repository:

```bash
gh extension install yohn-jp/gh-inari
gh inari --version
```

## Breaking changes

None intended for supported command semantics.

## Known limitations

- The supported Node.js range remains `>=22.13`.
- Unsupported GitHub-native fields and browser-only behavior continue to
  fail closed as documented in the main README.
- Repository-sourced governance requires the caller's authenticated `gh`
  installation.
