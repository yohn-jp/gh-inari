# gh-inari 0.18.0

## Summary

0.18.0 is the pre-refactoring checkpoint after the Local Runtime convergence work in 0.17.1. It strengthens Implementation Session authority and operator-facing Local Runtime behavior before the next multi-repository Console and architecture-refactoring phase.

## Highlights

- **Implementation Source-bound Sessions**: Implementation Sessions bind their signed authority to the canonical Source Issue set. Source-rooted Change lifecycle operations are authorized only for current, same-repository Sources; unrelated, removed, cross-repository, and Implementation-root substitutions fail closed.
- **Bounded multi-Source authority**: Source-bound lifecycle claims are validated against the signed Implementation Source set without imposing the historical Session-wide 16-claim ceiling on valid Source lifecycle claims.
- **Local Runtime diagnostics**: Admission, Executor, and supervisor runtime paths emit bounded structured operational logs and preserve foreground child diagnostics without changing authorization semantics.
- **Static hosted onboarding descriptor**: hosted onboarding metadata is served as a static Workers asset rather than requiring Worker execution for immutable descriptor content.
- **CLI/operator polish**: the CLI presentation and help surface include the current Inari product header and operator-oriented command presentation improvements.

## Fixed

- Implementation Session Change roots can no longer escape the canonical Source set through task/root ambiguity.
- A Source removed from the current Implementation contract is denied even when an older Session still names it.
- Source-bound lifecycle authority supports Implementations with more than three canonical Sources while retaining the existing global ceiling for unrelated claims.
- Runtime logging remains secret-safe and bounded across request, startup, readiness, shutdown, and unexpected-exit paths.

## Behavioral changes

Implementation Sessions now carry and revalidate the canonical Source set as part of their authorization contract. Automation that previously assumed an Implementation Session could operate on arbitrary Issue-rooted Changes must use a canonical Source Issue or the explicit Implementation compatibility authority where defined.

No intentional breaking change is made to successful ordinary Issue/PR governance workflows.

## Upgrade instructions

```bash
npm install -g gh-inari@0.18.0
inari --version --json
```

Existing Local Runtime setup from 0.17.1 remains the supported upgrade base.

## Breaking changes

No intentional breaking change to the supported CLI/setup path.

This is a pre-1.0 minor release because Session authorization semantics and Local Runtime operational surfaces have materially evolved since 0.17.1.

## Known limitations

- The multi-repository repository registry/custody work currently lives on Epic #1186 and is not included in this main-based release.
- GitHub App Manifest provisioning, canonical Connect/Disconnect lifecycle, unified multi-repository Local Console, Session observability, and their integrated certification remain follow-up work in #1188–#1192.
- The broader architecture refactoring planned after this checkpoint is intentionally not part of 0.18.0.
