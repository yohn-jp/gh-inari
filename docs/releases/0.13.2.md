# gh-inari 0.13.2

## Summary

0.13.2 is a reliability patch following 0.13.0. It supersedes the 0.13.1
candidate, which was never published to npm: 0.13.1's self-dogfood release
certification caught a release-blocking regression (#801) in the `change
ready` GraphQL mutation before publication. 0.13.2 carries the same fixes
0.13.1 was prepared with, plus the fix for that regression. No CLI flag,
schema, or public export changed.

## Fixed

- Change handoff owner/name locators are now bound to canonical
  repository host/ID evidence, rejecting mismatched locators
  deterministically instead of letting them slip through (#752, #790).
- Runtime minimum-version checks now implement bounded SemVer precedence,
  including prerelease ordering, build metadata, and `v` prefixes (#758,
  #793).
- Direct MCP stdio `--repo` option parsing now consistently targets a
  GitHub repository, matching the CLI contract; `--repository-root`
  remains the explicit selector for the local working directory (#760,
  #794).
- Optional Actions job inspection failures (403, 5xx, timeout) are now
  treated as bounded diagnostics and no longer block retrieval of a
  valid correlated result (#740, #791).
- Marker-named semantic templates are now resolved automatically by
  their manifest-managed source path during existing Issue checks and
  explanations (#781, #795).
- The `MARK_PULL_REQUEST_READY` GraphQL mutation now includes
  `operationName` again; it was silently dropped when the mutation was
  routed through the shared provider GraphQL transport, which could
  cause `change ready` to fail depending on provider-side operation
  dispatch (#801, #802).

## Behavioral changes

None beyond the fixes above.

## Upgrade

```bash
npm install --global gh-inari@0.13.2
inari --version --json
```

For pre-release validation from the release branch:

```bash
pnpm install --frozen-lockfile
pnpm run verify
npm pack
```

## Breaking changes

None.

## Known limitations

The `v0.13.1` GitHub Release and tag exist but were never published to
npm; self-dogfood release certification blocked publication after
finding #801. They remain as an immutable record of the caught
candidate, per the release governance worked example in
`docs/releases/GOVERNANCE.md`. Use `0.13.2`.
