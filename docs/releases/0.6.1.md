# gh-inari 0.6.1

## Summary

0.6.1 fixes two rough edges found while exercising 0.6.0's governed
commands directly: `--repository` had no `--repo`/`-R` alias matching
gh's own flag surface, and `issue check`/`pr check` on a wrong-template
match produced duplicated, noisy JSON output.

## Fixed

- `--repo <r>` and `-R <r>` are now accepted as aliases for
  `--repository <r>` on all governed `issue`/`pr` commands. Previously
  only `--repository` was accepted; `--repo`, which works on nearly
  every `gh` subcommand, failed with
  `INVALID_OPTION: Unknown option --repo.`
- `issue check`/`pr check` output on a `wrong-template` classification
  no longer duplicates its diagnostic list under both `diagnostics` and
  `violations`, and no longer emits one near-identical
  `EXISTING_WRONG_TEMPLATE` entry per candidate template. A single
  diagnostic now summarizes the attempted templates, and a new
  `attemptedTemplates` array lists them explicitly.

## Behavioral changes

- `issue check`/`pr check` JSON output drops the `violations` key on a
  `wrong-template` classification; `diagnostics` remains and is no
  longer duplicated. Scripts reading `violations` for this case must
  switch to `diagnostics` (now a single summarizing entry) or the new
  `attemptedTemplates` array. The `valid`/`normalizable`/`status`/
  `classification` fields are unchanged.

## Upgrade instructions

Install the published package:

```bash
npm install --global gh-inari@0.6.1
```

Or install the extension directly from this repository:

```bash
gh extension install yohn-jp/gh-inari
gh inari --version
```

No template-format or governance-source migration is required for this
release.

## Breaking changes

None to command availability or successful-path output shapes. The
`violations`-key removal described under
[Behavioral changes](#behavioral-changes) only affects the
`wrong-template` check/explain failure case, and only for callers doing
strict/exact JSON-shape matching on that case.

## Known limitations

- The supported Node.js range remains `>=22.13`.
- Unsupported GitHub-native fields and browser-only behavior continue to
  fail closed as documented in the main README.
- Repository-sourced governance requires the caller's authenticated `gh`
  installation.
- Local `--from <file>` and stdin artifact input are bounded to 1 MiB.
- `gh inari template sync` does not yet detect or clean up stale
  generated files left behind by a semantic-source layout change.
- `--help=json` (machine-readable help projected from the same command
  metadata) is not yet implemented; tracked under #86.
