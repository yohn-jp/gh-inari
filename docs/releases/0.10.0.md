# gh-inari 0.10.0

## Summary

0.10.0 establishes a stable authority and invocation baseline for governed agent workflows before the next semantic expansion of Inari. Command contracts, operational skills, CLI help, and runtime diagnostics now project from explicit authorities instead of drifting handwritten representations, while Issue and Pull Request creation can resolve governed templates deterministically when callers omit `--template`.

This release is intended as the stable pre-expansion baseline for normal repository and agent use.

## Highlights

- Canonical command and agent contract authority:
  - Command identity, option ownership, routing metadata, help, and agent-facing workflow projections are derived from shared authorities.
  - Option scope is derived from command ownership rather than maintained as a second inverse mapping.
  - Skill scenarios and command discovery stay aligned with the executable CLI contract.
- Canonical `inari` invocation:
  - `inari` is the primary executable identity while `gh-inari` remains available for compatibility.
  - Diagnostics probe the actual canonical executable instead of inferring readiness from package metadata alone.
  - Missing, stale, and unavailable canonical invocation states fail closed with bounded diagnostics.
- Contract-derived create guidance:
  - Create help projects field semantics from the selected artifact contract.
  - Generic array fields repeat as `<value>` while checklist fields repeat as `<option-id>`.
  - Template selection is no longer represented as unconditionally required when deterministic resolution can select it.
- Deterministic governed template resolution:
  - Issue and Pull Request creation share one resolver authority.
  - Resolution precedence is explicit selector → repository-configured default → sole candidate → interactive selection.
  - Multiple candidates in non-interactive environments fail deterministically instead of guessing.
  - Ambiguity diagnostics expose a bounded candidate set and explicit recovery guidance.
  - Repository template-resolution configuration participates in governance provenance and freshness checks without overriding an explicit selector.

## Fixed

- Routing preserves governed command interpretation when option values resemble command tokens.
- Canonical invocation diagnostics now verify the executable that agents are instructed to call.
- Create help no longer conflates generic array values with checklist option identifiers.
- Explicit template selection remains authoritative even when repository template-resolution configuration exists, while that configuration is still tracked as a governance input for mutation freshness.
- Generated package output includes the split CLI core and exported template resolver surface.

## Behavioral changes

- `--template` may be omitted for governed Issue and Pull Request creation when Inari can resolve a template deterministically.
- When omitted, template resolution follows this precedence:
  1. repository-configured default;
  2. sole available candidate;
  3. deterministic interactive selection when a TTY is available;
  4. bounded failure when multiple candidates remain in a non-interactive environment.
- An explicit `--template` remains authoritative and bypasses configured-default semantics.
- Repositories may define governed defaults in `.github/inari/template-resolution.yml`.
- Agents should treat `inari` as the canonical invocation and use live command/skill projections rather than maintaining copied CLI syntax.

## Upgrade instructions

Install the published package:

```bash
npm install --global gh-inari@0.10.0
inari --version
```

Existing successful 0.9 workflows with explicit template selection remain supported. Repositories can adopt deterministic omitted-template creation incrementally by configuring a default, reducing the candidate set to one, or allowing interactive selection where appropriate.

## Breaking changes

No intentional breaking change to successful governed 0.9 Issue/PR workflows.

0.10.0 is a minor release because it introduces deterministic omitted-template resolution, strengthens canonical invocation semantics, and consolidates command/agent authority. Compatibility invocation through `gh-inari` remains available, but `inari` is the canonical executable identity for operational guidance and diagnostics.

## Known limitations

- The supported Node.js range remains `>=22.13`.
- Multiple templates without an explicit selector or configured default require an interactive TTY; non-interactive callers must resolve the ambiguity explicitly.
- Template-resolution defaults are repository governance inputs and therefore participate in mutation freshness checks.
- GitHub-native Issue lifecycle relationships are not part of this release; lifecycle semantics remain a subsequent development wave.
- Free-form Markdown and natural-language semantic inference remain out of scope; unsupported or ambiguous representations fail closed.
- GitHub authentication and authorization remain supplied by the caller's environment.
