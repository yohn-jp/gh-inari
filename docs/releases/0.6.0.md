# gh-inari 0.6.0

## Summary

0.6.0 repositions `inari` as the canonical agent- and human-facing entry
point, ahead of the extension form (`gh inari`), and makes `--help`
progressive by command depth instead of dumping the full command tree at
every level. This is the first step of #86.

## Highlights

- New npm bin `inari`, alongside the existing `gh-inari`, both resolving
  to the same entrypoint. `npm install --global gh-inari` now gives you
  `inari` directly, without requiring `gh extension install`.
- README repositions `inari` as the canonical invocation and documents
  the agent execution-hook rewrite contract (`argv[0] gh -> inari`),
  including the invariant that hooks must not maintain their own
  governed-command table -- Inari remains the sole routing authority.
  `gh extension install` / `gh inari` remain fully supported as a
  compatibility path.
- `--help` is now progressive:
  - `inari --help` -- lists the governed domains (`issue`, `pr`,
    `template`) and states that everything else passes through to `gh`.
  - `inari issue --help` / `inari pr --help` / `inari template --help`
    -- lists only that domain's operations.
  - `inari issue create --help` (and other leaf commands) -- shows that
    command's usage and a minimal example.
  - `inari --help=full` -- the complete command and option reference,
    preserved for exhaustive discoverability.

## Upgrade instructions

Install the published package:

```bash
npm install --global gh-inari@0.6.0
inari --version
```

Or install the extension directly from this repository:

```bash
gh extension install yohn-jp/gh-inari
gh inari --version
```

No template-format or governance-source migration is required for this
release.

## Breaking changes

None for governed commands or their output shapes.

One passthrough-routing fix changes behavior for a narrow case: `--help`
on a command Inari does not govern (e.g. `inari repo view --help`,
`inari pr list --help`) previously printed Inari's own help text instead
of delegating to the real `gh` binary. It now falls through to
`gh <command> --help`, consistent with how execution of the same
commands already delegates. Scripts that parsed Inari's help output for
an unowned command are affected; scripts that parse `gh`'s own help
output are not.

## Known limitations

- The supported Node.js range remains `>=22.13`.
- Unsupported GitHub-native fields and browser-only behavior continue to
  fail closed as documented in the main README.
- Repository-sourced governance requires the caller's authenticated `gh`
  installation.
- Local `--from <file>` and stdin artifact input are bounded to 1 MiB.
- `gh inari template sync` does not yet detect or clean up stale
  generated files left behind by a semantic-source layout change.
- `--help=json` (machine-readable help projected from the same command
  metadata) is not yet implemented; tracked under #86.
- The agent execution-hook rewrite (`argv[0] gh -> inari`) is documented
  but not yet shipped as a standalone integration primitive; tracked
  under #86.
