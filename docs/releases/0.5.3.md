# gh-inari 0.5.3

## Summary

0.5.3 extends Inari's semantic authority from creation into deterministic
remediation of already-existing Issues and pull requests. Four new
commands -- `check`, `edit`, `normalize`, and `sync` -- share one
transformation/diff pipeline (`src/reconciliation.ts`) built on the
existing canonical IR, parser, validator, renderer, governance freshness
check, and post-effect reconciliation boundary, rather than introducing a
second semantic model or a generic GitHub edit path.

## Highlights

- `gh inari issue|pr check <number>` -- read-only. Classifies an existing
  artifact as valid-current, non-canonical, semantically-invalid,
  unsupported, or ambiguous, without mutating GitHub.
- `gh inari issue|pr edit <number> --from <file.json> [--dry-run]` --
  applies an explicit semantic JSON patch. Never accepts raw Markdown as
  the mutation contract.
- `gh inari issue|pr normalize <number> [--dry-run]` -- re-renders a
  parseable, valid artifact through the canonical renderer. Fails closed
  when preservation of existing semantic values can't be proven; an
  already-canonical artifact is an explicit no-op.
- `gh inari issue|pr sync <number> --from <file.json> [--dry-run]` --
  treats the input as the complete desired semantic state and converges
  the remote artifact deterministically. Repeated `sync` against a
  converged artifact is an idempotent no-op.
- `edit`, `normalize`, and `sync` all support `--dry-run`, which computes
  the same bounded semantic/rendered diff as a live mutation without
  calling the `gh` adapter.

## Upgrade instructions

Install the published package:

```bash
npm install --global gh-inari@0.5.3
```

Or install the extension directly from this repository:

```bash
gh extension install yohn-jp/gh-inari
gh inari --version
```

No template-format or governance-source migration is required for this
release.

## Breaking changes

None. `check`, `edit`, `normalize`, and `sync` are new commands; existing
commands and output shapes are unchanged.

## Known limitations

- The supported Node.js range remains `>=22.13`.
- Unsupported GitHub-native fields and browser-only behavior continue to
  fail closed as documented in the main README.
- Repository-sourced governance requires the caller's authenticated `gh`
  installation.
- Local `--from <file>` and stdin artifact input are bounded to 1 MiB.
- `gh inari template sync` does not yet detect or clean up stale
  generated files left behind by a semantic-source layout change.
