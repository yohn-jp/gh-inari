# gh-inari 0.7.0

## Summary

0.7.0 adds the bounded `inari skill [scenario]` surface for operational
playbooks and ships Inari as a Codex Plugin through the same `gh-inari`
npm package. CLI consumers and Codex users now receive one versioned
distribution with the executable, plugin manifest, and Skill file together.

## Highlights

- New `inari skill` command:
  - `inari skill` lists the available operational playbook scenarios.
  - `inari skill <scenario>` prints the selected workflow and invariants.
  - `--json` provides the corresponding structured projection for agents.
  - Output is bounded and the playbook model is versioned for predictable
    agent consumption.
- Codex Plugin packaging in the existing `gh-inari` distribution:
  - `.codex-plugin/plugin.json` declares the plugin and its Skill path.
  - `skills/inari/SKILL.md` explains when to use Inari and routes agents to
    the live `inari skill` command for exact operational playbooks.
  - No separate plugin package or MCP surface is required.
- Package and end-to-end checks verify the packed artifact contains the
  executable CLI, all declared export targets, `.codex-plugin/plugin.json`,
  and `skills/inari/SKILL.md`, then smoke-test the installed tarball.

## Upgrade instructions

Install the published package:

```bash
npm install --global gh-inari@0.7.0
inari --version
inari skill
```

Or install the extension directly from this repository:

```bash
gh extension install yohn-jp/gh-inari
gh inari --version
```

No template-format or governance-source migration is required for this
release.

## Breaking changes

None to existing governed command contracts or successful-path output
shapes. The new `inari skill` and Codex Plugin surfaces are additive.

## Known limitations

- The supported Node.js range remains `>=22.13`.
- Unsupported GitHub-native fields and browser-only behavior continue to
  fail closed as documented in the main README.
- Repository-sourced governance requires the caller's authenticated `gh`
  installation.
- Local `--from <file>` and stdin artifact input are bounded to 1 MiB.
- `gh inari template sync` does not yet detect or clean up stale
  generated files left behind by a semantic-source layout change.
- `--help=json` (machine-readable help projected from the same command
  metadata) is not yet implemented; tracked under #86.
