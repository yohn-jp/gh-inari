# gh-inari 0.11.0

## Summary

0.11.0 lands the first working slice of the governed Change control plane
described in `docs/CHANGE_CONTROL_PLANE.md`: a new `inari change` command
family that issues, inspects, readies, and aborts a governed Change (one
Issue, one canonical branch, one canonical Draft PR) through a trusted
remote executor. It also converges Inari's Issue, Branch, and PR handling
onto one Semantic Artifact Core, migrates Change lifecycle control flow to
an XState state machine, adds a native local MCP surface, and adds
GitHub-native Issue relation (dependency) observation. Existing
artifact-level Issue/PR commands (`create`, `edit`, `normalize`, `sync`,
`validate`, `render`) are unchanged and remain fully supported.

## Highlights

- **Governed Change lifecycle (`inari change`)**:
  - `inari change issue <number>`, `change show <number>`, `change ready
<number>`, and `change abort <number>` issue, inspect, promote, and stop a
    governed Change, returning bounded JSON projections (#297–#362; see
    `docs/CHANGE_CONTROL_PLANE.md`).
  - Change issuance is idempotent (create-or-return-existing) and
    compensates a partially created canonical branch if Draft PR creation
    fails, using a SHA-conditional delete so an advanced branch is never
    torn down by mistake.
  - Change lifecycle control flow (issuance, ready, abort, and their
    compensation/recovery paths) is now implemented as an XState v5
    statechart; semantic authority stays in Inari Core pure functions and
    XState owns only control flow (#347, #349, #353–#355, #359, #362; see
    `docs/XSTATE_CHANGE_MACHINE.md`).
  - Authoritative Change transitions run through a trusted remote
    executor (`TrustedChangeExecutor`) under a least-privilege Inari
    issuer GitHub App identity; requester, issuer, implementer, reviewer,
    and merger identities remain distinct (see `docs/INARI_ISSUER_APP.md`).
  - Change provenance is validated from the pull request's own head and
    projected into merge admission, so a noncanonical PR cannot pass as a
    governed Change (#328, #329, #340, #341, #358).
- **Semantic Artifact Core / template reconciliation**:
  - Issue, Branch, and PR handling now compile through one effective
    artifact contract, deterministic projection, and reconciliation
    pipeline instead of three parallel implementations (#297, #298, #290,
    #334–#337; see `docs/SEMANTIC_ARTIFACT_CONTRACTS.md`).
  - Legacy artifact-level compatibility (`create`/`edit`/`normalize`/
    `sync`) now consumes the same Semantic Artifact Core rather than a
    separate code path (#335).
  - Repository-owned Artifact Contracts are projected into native GitHub
    Issue Form / PR templates (#334).
- **Semantic Branch and Semantic Pull Request projection/observation**:
  - New deterministic projection, drift observation, and local execution
    for semantic Branches and PRs, exposed through the CLI and a native
    local MCP surface (#299–#324, #332, #333; see
    `docs/NATIVE_MCP_ISSUER_GATEWAY.md`).
  - `inari` now exposes semantic observation-drift checks so a caller can
    detect when GitHub's projected state has drifted from the
    repository-declared contract before mutating anything.
- **Issue dependency / relation observation**:
  - A GitHub-native Issue relation observation adapter reads GitHub's own
    Issue-to-Issue relations and Issue milestone / PR labels, assignees,
    milestone, and reviewers into Inari's semantic model (#291, #292).
- **Operational / governance**:
  - `dist/**` sync to `main` now authenticates through a dedicated
    `inari-dist-sync` GitHub App instead of the ambient `GITHUB_TOKEN`,
    narrowing the bypass identity that can push to `main` to one
    least-privilege, `contents: write`-only App (#356; see the "Trusted
    dist sync" section of `docs/releases/GOVERNANCE.md`).
  - CI is now the sole writer of tracked `dist/**` artifacts (#344).
  - `branch-naming-authority.mjs` / `.d.mts` are now published in the npm
    package `files` list, so external governance consumers (e.g. the
    shared `pr-governance.yml` workflow) can depend on the published
    package rather than a repository-local copy.
  - New public subpath exports: `gh-inari/change`,
    `gh-inari/change-executor`, `gh-inari/change-trusted-executor`,
    `gh-inari/mcp`, and the `semantic-{issue,branch,pr}-{projection,observation}`
    family, plus `gh-inari/semantic-issue-lifecycle` and
    `gh-inari/semantic-branch-executor`.

## Fixed

- Change branch compensation only deletes the exact branch generation the
  issuer created; a branch that advanced after issuance is left alone
  (#338).
- Stale semantic native projections are rejected instead of silently
  reused (#339).
- Absent branch policy is distinguished from a local policy _read
  failure_, so a missing policy is no longer misreported as an error
  (#331, #274).
- Trusted executor checkout is pinned to the dispatching workflow's own
  commit SHA, closing a window where a later push to the branch could
  change what the executor runs (#330).
- Change requester identity is bound to the trusted actor rather than
  inferred, and the Change provenance validator runs from the pull
  request's head, not the base (#329, #358).
- Missing PR merge evidence now fails closed instead of assuming success
  (#328).
- Change failure diagnostics are bounded rather than potentially
  unbounded (#357).
- Task-list Markdown that was intentionally part of canonical field
  content is preserved through round trips instead of being stripped
  (#293).

## Behavioral changes

- `inari change *` is a new, additive command family. It does not replace
  or deprecate `issue`/`pr` `create`/`edit`/`normalize`/`sync` in this
  release; both remain supported while the Change workflow rolls out (see
  `docs/CHANGE_CONTROL_PLANE.md` §26).
- `change show` is read-only; `change issue`, `change ready`, and `change
abort` dispatch a trusted remote executor. Workflow names, dispatch
  inputs, Actions job structure, and privileged App credentials are not
  CLI inputs and are not part of the public contract.
- Issue, Branch, and PR artifact handling is now internally unified on
  Semantic Artifact Core. No caller-visible schema, contract, or CLI flag
  changes are intended as a result; this is documented here because it is
  the architectural precondition for the rest of this release and a
  regression here would be user-visible.

## Upgrade instructions

```bash
npm install --global gh-inari@0.11.0
inari --version
```

Existing 0.10.x local Issue/PR workflows (`create`, `edit`, `normalize`,
`sync`, `validate`, `render`) require no changes. Adopting `inari change
*` is optional and requires the repository to have the Inari issuer
GitHub App and a trusted-executor Actions workflow configured; without
that configuration, `change issue`/`ready`/`abort` fail closed rather than
falling back to an unprivileged local mutation.

**Node.js requirement raised**: `engines.node` moved from `>=22.13` to
`>=24` (landed with #274). Installs on Node 22 or 23 that previously
worked will now fail the engines check; upgrade the Node runtime before
upgrading this package.

## Breaking changes

- **Node.js `>=24` is now required** (previously `>=22.13`). This is the
  one breaking change in this release for existing installs; see Upgrade
  instructions.
- No breaking change to existing governed Issue/PR artifact contracts,
  schemas, or CLI flags. `inari change *` is new surface, not a
  replacement for existing commands, in this release.

## Known limitations

- `change ready` and `change abort` require the repository's trusted
  Actions executor and Inari issuer GitHub App to be configured; Inari
  does not provision that infrastructure itself.
- The native MCP issuer gateway described in
  `docs/NATIVE_MCP_ISSUER_GATEWAY.md` is architecture and a local MCP
  surface in this release; the hosted MCP gateway (external ingress
  replacing GitHub Actions as the CLI's remote transport) is not shipped
  in 0.11.0.
- Issue relation/dependency observation reads GitHub-native Issue
  relations; it does not yet mutate or reconcile GitHub-native dependency
  state (carried forward from 0.9.0).
- Free-form Markdown and natural-language semantic inference remain out
  of scope; unsupported or ambiguous representations fail closed.
- GitHub authentication and authorization remain supplied by the caller's
  environment.
