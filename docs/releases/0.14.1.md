# gh-inari 0.14.1

## Summary

0.14.1 supersedes the 0.14.0 candidate, which was never published to npm:
its `v0.14.0` tag/GitHub Release existed but `npm publish` failed because
the release-certification gate required a manually dispatched self-dogfood
workflow run that was not part of the documented release process (#897).
0.14.1 carries the same content 0.14.0 was prepared with, plus the fix for
that gate (#900) and an unrelated README hero-image swap. No CLI flag,
schema, or public export changed beyond what 0.14.0 already introduced.

## Highlights

Everything from the unpublished 0.14.0 candidate:

- **Repository Relay transport**: a deployment-neutral transport
  contract kernel (#828) with a deterministic, versioned delivery
  lifecycle covering pre-delivery retry safety and delivered-ambiguity
  recovery (#829), transport-only replay-resistant Ed25519 possession
  proof for relay connections (#830), a Hosted MCP Session executor
  adapter backed by the relay (#831), a Node-local relay WebSocket
  client and Session execution bridge (#832), a repository-scoped
  hibernatable Cloudflare Durable Object relay adapter (#833), a
  foreground Runtime connect surface exposed through the CLI (#835),
  operational bounds and secret-safe transport telemetry (connection
  count, in-flight jobs, message rate, deadlines, retention) (#837)
  wired into Cloudflare Workers Observability (#848), and a
  cross-deployment certification profile plus a real-deployment live
  certification mode (#839, #851).
- **Hosted MCP**: a bounded stateless Web-standard Streamable HTTP
  handler for the native Inari MCP catalog (#834), a separate
  Cloudflare Worker front door composing native MCP and Repository
  Relay ingress (#836), a custom-domain route at `mcp-inari.yohn.jp`
  plus a `wrangler.hosted.toml.sample` for other operators (#880), and
  registration of the live hosted server as a shared project MCP
  server via `.mcp.json` (#884).
- **Execution-scope v1**: the existing implementation-execution-scope
  projection is frozen as the public v1 execution authority (#863)
  with frozen selector semantics (#864), bounded applicability
  validation (#865), and a product-neutral conformance corpus with a
  deterministic Inari producer oracle (#866).
- **Session signer**: a transport-neutral Session signer contract
  (#892), a narrow Session MCP client adapter (#893), adaptation of
  pre-issued Session credential bundles to the canonical signer (#894),
  and certification of managed/bundle signer profiles through the
  privileged MCP handoff (#895).
- Default PR template resolution when `--template` is omitted (#876)
  and read-only discovery now returns all candidate schemas for
  ambiguous templates instead of failing closed (#877).
- A preinstall script unlinks a symlinked `node_modules` before
  `pnpm install` runs inside a worktree, so installing there no longer
  mutates the main worktree's dependencies (#882).

New in 0.14.1:

- The `publish` release-certification gate (`scripts/verify-release-certification.mjs`)
  no longer requires a retained self-dogfood Actions artifact for the
  exact release SHA to certify a release. It still verifies one when
  present, and a dogfood run that exists and fails still fails the
  release; it is just no longer a mandatory, undocumented manual step
  (#897, #900).
- README hero banner image updated (#899).

## Fixed

- Governed Issue template marker emission is now aligned with semantic
  provenance while preserving native-path compatibility (#827).
- The Repository Relay Durable Object now uses a real
  `WebSocketRequestResponsePair` instance for `setWebSocketAutoResponse`
  and constructs the 101 WebSocket-upgrade `Response` with `.webSocket`
  passed in the constructor init instead of assigned after
  construction — both defects were only observable against the real
  Workers runtime, not the controlled/injected-transport harness
  (#852, #878).
- Production relay possession admission and expired-result handling
  have been repaired (#841, #849).
- Admitted Runtime connections are now assigned deterministic transport
  generations, and replacement state is isolated across Durable Object
  reconstruction (#842, #850).
- The release-certification gate no longer blocks npm publication on an
  undocumented manual self-dogfood dispatch step (#897, #900).

## Behavioral changes

0.14.1 is a pre-1.0 minor-line release carrying 0.14.0's substantial
contract evolution. It introduces the Repository Relay, Hosted MCP
Worker, execution-scope v1, and Session signer as new surfaces; existing
CLI commands, library subpaths, and Change/Issue/PR contracts are
unchanged. Consumers relying on agent-authority or Session/Implementation
lifecycle APIs should validate against the packed 0.14.1 artifact before
upgrading production automation, per the repository's pre-1.0 versioning
policy.

## Upgrade

```bash
npm install --global gh-inari@0.14.1
inari --version --json
```

For pre-release validation from the release branch:

```bash
pnpm install --frozen-lockfile
pnpm run verify
npm pack
```

## Breaking changes

None.

## Known limitations

The `v0.14.0` GitHub Release and tag were deleted before any npm
publication was attempted; certification caught the undocumented
release-gate defect (#897) before publishing anything. There is no
`gh-inari@0.14.0` on npm and there never was. Use `0.14.1`.
