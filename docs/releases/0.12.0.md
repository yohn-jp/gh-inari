# gh-inari 0.12.0

## Summary

0.12.0 lands the Session App execution surface: a stateless, trust-verified
HTTP execution path (a "direct App") that lets a Runtime Authority issue
short-lived Session credentials and have a governed Change executed through
either an installed CLI App transport or a Cloudflare Worker deployment,
without a long-lived privileged token in the caller's hands. It builds on
the Change control plane shipped in 0.11.0: capability admission,
capability execution provenance, and branch-advance authority now gate what
a Session-authorized request may do, and a new `src/worker.ts` deployment
target runs the same execution contract at the edge. This cycle also closes
out the Golden Path architecture epic (status/next-action projection,
retry/abort/recovery, native Issue relationship management) that started
in 0.11.0.

## Highlights

- **Session App execution**:
  - Stateless direct App HTTP transport exposing a `POST /v1/execute` wire
    contract (#377, #489), plus an installed CLI App transport and change
    publish path (#490).
  - Cloudflare Worker deployment of the same direct-App execution contract
    (#491; see `docs/CLOUDFLARE_WORKER_DEPLOYMENT.md`), with new `pnpm`
    scripts `worker:build`, `worker:deploy`, `worker:dev` (`verify` now
    runs `worker:build`).
  - Runtime Authority trust-root lifecycle and key generation (#390/#478,
    #391, #393, #394), managed Session certificate issuance (#371/#471),
    manual short-lived Session credential bundle issuance (#474), and a
    signed semantic request envelope with Session proof-of-possession
    (#473).
  - Semantic capability admission (#481), capability execution provenance
    (#376/#482), and session-authorized Change execution composition
    (#483) gate what an admitted Session may execute; delegated writes are
    prevented from modifying capability trust roots (#370).
  - Runtime trust and Session delegation are verified at the App boundary
    (#477); a reusable GitHub App installation credential broker backs
    both transports (#472).
  - New `docs/AGENT_CAPABILITY_AUTHORIZATION.md` describes this
    architecture; the prior hosted-gateway design is retained as
    `docs/NATIVE_MCP_ISSUER_GATEWAY_LEGACY.md`.
- **Golden Path epic completion**:
  - Executable Golden Path entry/preflight composition (#424), governed
    transition from implementation to review (#426), and canonical
    implementation handoff for Nawabari (#425).
  - Machine-readable Golden Path status and next action (#428), safe
    retry/abort/recovery projection (#429), and status bound to converged
    Change and XState evidence (#430), all exposed through MCP (#432 area).
  - GitHub-native Issue relationship management through Inari semantic
    authority (#427); Golden Path repository governance discovery is now
    bounded and adaptive (#432); a canonical `inari skill golden-path`
    scenario was added (#431).
  - `docs/GOLDEN_PATH_ARCHITECTURE.md` documents this as an architecture
    gate only — see Known limitations.
- **Distribution**:
  - `gh-inari` migrated to precompiled GitHub Release extension binaries
    as the primary install path (#445); git-clone install is now a
    fallback, not the default (carried into this release's docs).

## Fixed

- Repository-wide CodeQL alerts eliminated (#480, #487), including a
  TOCTOU and a property-injection finding in the mock provider.
- Branch-advance authority hardened: bounded branch advance contract
  restored (#488), branch advance authority preserved, canonical branch
  advance request admitted, canonical capability admission subject used
  consistently, exact branch advance replay target verified, branch
  advance public Git seam narrowed, and #466's verified provenance now
  required for a successful `branch.advance`.
- Direct App provenance and branch request are now preserved correctly
  through the execution path.
- PR artifact whitespace normalization scoped correctly (#494).
- Change provenance PR evidence bounded (#398); `change.issue` wired to
  canonical governed PR template rendering; Golden Path fails closed when
  its authority is unavailable; Phase 2 Golden Path integration gaps
  closed before merge (#444).

## Behavioral changes

- Precompiled GitHub Release binaries are the default `gh extension
install`/`upgrade` path; no Node runtime is required on the installing
  machine for that path (#445, carried from the 0.11.0 distribution
  change).
- New optional Session App execution surface (direct App HTTP transport,
  CLI App transport, Cloudflare Worker deployment) is additive. It
  requires new environment configuration when used —
  `INARI_GITHUB_APP_ID`, `INARI_GITHUB_APP_PRIVATE_KEY`,
  `INARI_GITHUB_APP_INSTALLATION_ID`, `INARI_TARGET_REPOSITORY_OWNER`,
  `INARI_TARGET_REPOSITORY_NAME`, `INARI_TARGET_REPOSITORY_HOST`, and
  optionally `INARI_TARGET_REPOSITORY_NODE_ID`, `INARI_MAX_BODY_BYTES`,
  `INARI_GITHUB_API_REQUEST_TIMEOUT_MS` — but does not change existing
  local CLI or `inari change *` behavior when unused.
- New public subpath exports: `gh-inari/change-handoff`,
  `gh-inari/golden-path-review`, `gh-inari/golden-path-entry`,
  `gh-inari/golden-path-recovery`, `gh-inari/semantic-issue-relations`,
  `gh-inari/semantic-issue-relation-executor`, `gh-inari/agent-authority`,
  `gh-inari/session-authorized-change-executor`,
  `gh-inari/golden-path-status`.
- New dependencies: `wrangler`, `esbuild`, `@xstate/graph`, `postject`
  (devDependencies); `zod` bumped to 4.5.4.

## Upgrade instructions

```bash
npm install --global gh-inari@0.12.0
inari --version
```

Existing local Issue/PR/Change workflows require no changes. Adopting
Session App execution (direct App HTTP transport or the Cloudflare Worker
deployment) is optional and requires the environment configuration listed
above; without it, this surface is not invoked and existing CLI/`inari
change *` behavior is unaffected.

## Breaking changes

None. `engines.node` remains `>=24` (unchanged from 0.11.0). No existing
export, CLI flag, or artifact contract was removed or renamed.

## Known limitations

- `docs/GOLDEN_PATH_ARCHITECTURE.md` is explicitly an architecture gate:
  it does not itself add a Golden Path CLI, runtime orchestration code, a
  new persistence store, or an operational playbook implementation.
- The Cloudflare Worker deployment holds no persistent session/policy
  store; end-to-end proof of a live `POST /v1/execute` against a real
  Session-signed request is tracked as separate follow-up work (#378), not
  shipped in this deployment.
- `docs/AGENT_CAPABILITY_AUTHORIZATION.md` is explicit that strict
  one-shot/replay semantics cannot be fully proven by a stateless
  signature alone, and that Runtime trust does not imply trust for every
  operation; callers must not assume replay protection beyond what the
  document states.
- Issue relation/dependency observation still reads GitHub-native
  relations only; it does not mutate or reconcile GitHub-native dependency
  state (carried forward from 0.9.0/0.11.0).
- Free-form Markdown and natural-language semantic inference remain out of
  scope; unsupported or ambiguous representations fail closed.
- GitHub authentication and authorization remain supplied by the caller's
  environment.
