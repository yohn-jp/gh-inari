# gh-inari 0.1.0

## Summary

First public release of Inari. This release ships `gh-inari` as a
standalone CLI and as a `gh` extension (`gh inari`) that turns a
repository's native Issue Forms and pull request templates into
deterministic, typed contracts — validating structured input, rendering
canonical Markdown, and performing GitHub mutations only after the
contract, input, and rendered artifact have all passed validation.

## Highlights

- **Contract compiler**: `.github/ISSUE_TEMPLATE/**` and pull request
  templates under the repository root, `docs/`, or `.github/` (including
  `PULL_REQUEST_TEMPLATE/` directories) are discovered and compiled into a
  typed intermediate representation. Supported Issue Form nodes are
  `input`, `textarea`, single- and multi-select `dropdown`, `checkboxes`,
  and `markdown`; browser-only or ambiguous behavior (uploads,
  unsupported textarea rendering modes) fails closed.
- **Optional PR policy overlay**: a small versioned overlay
  (`version: 1`) can add constraints — linked-Issue requirement, minimum
  section length, checklist completion — on top of native PR Markdown
  without changing section order or content. One policy file can bind
  multiple native templates. References must match native section and
  template identities; unknown or ambiguous references fail closed.
- **Full command surface**: `template list`, `issue schema` /
  `validate` / `render` / `create`, the same set for `pr`, plus
  `issue validate <number>`, `pr validate <number>`, `issue explain
<number>`, and `pr explain <number>` for validating and diagnosing
  existing artifacts already on GitHub.
- **Fail-closed mutation pipeline**: every create path runs
  `resolve template -> compile contract -> validate semantic JSON ->
render canonical Markdown -> construct validated-rendered artifact ->
call gh`. Schema, validate, and render never call a remote mutation;
  invalid or unparseable state cannot reach the mutation adapter.
- **Library-first boundaries**: compiler, contract, validation,
  rendering, and the GitHub adapter are public library APIs
  (`gh-inari/contract`, `gh-inari/artifact`, `gh-inari/pr-policy`,
  `gh-inari/pull-request-template`), usable by future Actions or App
  adapters without invoking or scraping CLI output.
- **Release validation**: the exact `npm pack` tarball is built,
  inspected, installed in an isolated consumer, and smoke-tested as both
  the standalone executable and a discovered `gh` extension before
  publication.

## Upgrade instructions

Install the published package globally:

```bash
npm install --global gh-inari@0.1.0
```

Or run it without a global install:

```bash
npx -y gh-inari@0.1.0 --version
```

To register the installed package as a `gh` extension:

```bash
(cd "$(npm root --global)/gh-inari" && gh extension install .)
gh inari --help
```

No configuration migration is required for this first public release.

## Known limitations

- Issue Form top-level `assignees`, `projects`, and `type`, upload
  fields, and textarea code-block rendering are explicitly unsupported
  and fail closed rather than being approximated.
- The PR policy overlay covers GitHub closing references, minimum length,
  and checklist-completion constraints only; it does not replace or infer
  requirements beyond what is explicitly configured.
- Inari performs no GitHub authentication of its own; it delegates to
  the caller's existing `gh` installation and does not store
  credentials.
- The supported Node.js range is `>=22.13`.
