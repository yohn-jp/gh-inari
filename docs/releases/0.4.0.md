# gh-inari 0.4.0

## Summary

0.4.0 adds `.github/inari/` as an editable semantic template authority that
generates the native GitHub-facing Issue Forms and pull request template,
makes installation failures diagnosable, fixes a PR-contract validation gap
that rejected trailing content appended after the compiled template
structure, and migrates gh-inari's own CI/governance/publish workflows to
the organization's shared reusable workflows.

## Highlights

- **Semantic template authority**: migrated repositories keep editable
  template contracts as JSON under `.github/inari/` (`.github/inari/issues/<id>.json`,
  `.github/inari/pull-request.json`). `gh inari template sync` (and
  `--check`) regenerates the GitHub-native projections
  (`.github/ISSUE_TEMPLATE/**`, `.github/PULL_REQUEST_TEMPLATE.md`) from the
  semantic source; generation is byte-stable for unchanged input.
  `gh inari template import --from <path>` bootstraps an existing native
  template into the semantic directory using the supported native parser,
  failing closed on unsupported or ambiguous constructs. See
  [Semantic template authority](../SEMANTIC_TEMPLATES.md).
- **Diagnosable installation**: a broken or incomplete `gh-inari`
  installation now reports a specific, actionable diagnostic instead of an
  opaque failure.
- **Shared CI/governance/publish workflows**: gh-inari's own CI, CodeQL, PR
  and Issue governance, and npm publish pipelines now call the
  organization's reusable workflows in `yohn-jp/.github`, while gh-inari
  keeps ownership of its own semantic contracts and pinned validator
  version.

## Fixed

- Fixed the PR-contract validator classifying content appended after the
  compiled template structure (for example, an automated review-bot summary
  comment appended to a PR body) as `EXISTING_EXTRA_CONTENT` instead of
  preserving trailing documentation.

## Behavioral changes

- `.github/ISSUE_TEMPLATE/**` and `.github/PULL_REQUEST_TEMPLATE.md` are
  generated projections in a migrated repository and must not be edited
  directly; edit the corresponding `.github/inari/` semantic source and run
  `gh inari template sync`.
- `gh inari issue schema` / `gh inari pr schema` accept `--compact --json`
  for a field-identity-only view (type, requiredness, choices, relevant
  constraints) with fixed Markdown/YAML presentation omitted.

## Upgrade instructions

Install the published package:

```bash
npm install --global gh-inari@0.4.0
```

Or install the extension directly from this repository:

```bash
gh extension install yohn-jp/gh-inari
gh inari --version
```

Repositories that want the new semantic-template workflow should import
their existing native templates once:

```bash
gh inari template import --from .github/ISSUE_TEMPLATE/<file>.yml
gh inari template import --from .github/PULL_REQUEST_TEMPLATE.md
gh inari template sync
```

## Breaking changes

None intended for supported command semantics. Repositories that have
migrated to `.github/inari/` must run `gh inari template sync` after editing
a semantic source; editing the generated native files directly no longer
has effect on the next sync.

## Known limitations

- The supported Node.js range remains `>=22.13`.
- Unsupported GitHub-native fields and browser-only behavior continue to
  fail closed as documented in the main README.
- Repository-sourced governance requires the caller's authenticated `gh`
  installation.
