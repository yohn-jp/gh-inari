# gh-inari 0.2.0

## Summary

The 0.2.0 release closes the integration gaps at the repository-governance,
Issue Governance, and GitHub CLI extension distribution boundaries. Local and
authoritative remote operations now use the same native template path
semantics, while every governed command consistently resolves its source from
the selected repository.

## Highlights

- Remote PR template discovery now covers the same root, `docs/`, `.github/`,
  directory-template, `.md`/`.txt`, and filename-case semantics as local
  discovery.
- Authoritative PR policy compilation receives the complete remote template
  identity set and rejects stale or ambiguous multi-template bindings.
- `--repository` consistently binds schema, structured validation, rendering,
  creation preflight, existing-artifact validation, explanation, and
  authoritative template listing to the target repository.
- Issue Governance installs the pinned Node/pnpm runtime dependencies before
  invoking Inari and always leaves a deterministic diagnostic report when
  validation fails.
- The committed build plus the repository launcher support
  `gh extension install yohn-jp/gh-inari`; the launcher bootstraps production
  dependencies when a clean checkout is first executed.
- Source, packed `gh-inari`, and installed `gh inari` execution paths are
  covered by semantic parity smoke tests.

## Fixed

- Fixed valid Issues being marked `status:invalid` because the Issue
  Governance runner attempted to load `tsx` before installing dependencies.
- Fixed secondary Issue Governance failures caused by a missing diagnostic
  report after validator startup failures.
- Fixed remote governance silently omitting supported native PR templates and
  compiling policies without authoritative template identities.
- Fixed structured `validate` and `render` commands ignoring an explicit
  `--repository` override.

## Behavioral changes

- `template list --repository owner/name` now reports authoritative templates
  from that repository's default branch. Without an override it remains local.
- Invalid remote governance tree shapes fail closed with governance-source
  diagnostics.

## Upgrade instructions

Install the published package:

```bash
npm install --global gh-inari@0.2.0
```

Or install the extension directly from this repository:

```bash
gh extension install yohn-jp/gh-inari
gh inari --version
```

## Breaking changes

None intended for supported command semantics.

## Known limitations

- The supported Node.js range remains `>=22.13`.
- Unsupported GitHub-native fields and browser-only behavior continue to fail
  closed as documented in the main README.
- Repository-sourced governance requires the caller's authenticated `gh`
  installation.
