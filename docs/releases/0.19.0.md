# gh-inari 0.19.0

## Summary

0.19.0 is the architecture-convergence and runtime-recovery release after 0.18.0. It lands the renewed Product Architecture Canon and the implementation work integrated through the architecture-convergence Epic, moves major CLI presentation and path ownership onto CLI Canon 0.2, introduces schema-native governed artifact contracts and reconciliation, strengthens Source/Implementation publication and termination authority, adds the first signed remote repository-access contract, and restores the Local Runtime Session startup and packed-release path required for day-to-day development.

This release contains the complete governed history from v0.18.0 through main at `8597fc06f9895d032943023244dfa58d318be7ac` (90 commits). It is intentionally a pre-1.0 minor release rather than a patch because public CLI presentation, artifact contracts, authority boundaries, and architecture contracts materially changed.

## Highlights

- **Architecture convergence**: renew the Product Architecture Canon and detailed trust, runtime, artifact, publication, lifecycle, recovery, and verification contracts; converge implementation on the documented Core / Runtime / provider boundaries.
- **CLI Canon 0.2 public shell**: route the public CLI shell through CLI Canon, migrate Branch and Issue/PR View routes, and route local configuration path selection through Canon while retaining Inari-owned security and filesystem checks.
- **Schema-native Artifact Contract v2**: add a hermetic Draft 2020-12 JSON Schema runtime, schema-native Artifact Contract v2, Effective caller-schema derivation, semantic-template compilation, structured semantic materialization, and GitHub projection/observation for structured values.
- **Continuous governed artifact reconciliation**: parse artifacts through mdast/source positions, derive provider-normalized observation identities, reject stale mutation targets, and expose a versioned Core reconciliation operation with explicit unchanged, reconciled, blocked, retryable, and ambiguous outcomes.
- **Role-bound publication**: bind Implementation leaf, Source integration, Epic integration, and release publication to canonical governed identities and routes; add pure Source/Epic integration publication planning and exact task Session leaf PR claims.
- **Implementation task termination**: add versioned termination evidence, GitHub persistence, lifecycle/closure projection, Executor evidence/effect composition, and Admission enforcement at task-bound authorization boundaries.
- **Source acceptance authority**: add Source acceptance record validation, provider observation, protected default-branch acceptance policy loading, and reviewer-independence evaluation against immutable GitHub user identities.
- **Remote access foundation**: define the signed Repository Access Assertion v1 wire with request binding, repository/App/installation identity, issuer/audience/Relay binding, bounded lifetime, and Ed25519 verification.
- **Local operator authority foundation**: define signed local operator authentication and add the Runtime-owned Ed25519 public-key registry used by the forthcoming exact local integration grants.
- **Verification architecture**: make test discovery explicit, serialize Dashboard build ownership, separate release certification from routine verification, strengthen exact package inventory/install checks, and certify schema-native structured artifacts through installed public exports.
- **Local Runtime recovery**: allow provider-backed `POST /v1/branch-policy` up to the bounded 60-second provider-control deadline while preserving the 10-second fast-control and existing execution deadlines, restoring valid Session startup when GitHub branch-policy evidence exceeds ten seconds.
- **Release-path recovery**: align packed CLI certification with CLI Canon's canonical group Help and package-version presentation while separately retaining Inari's richer named `version --json` runtime/capability identity proof.

## Fixed

- Local Session startup no longer fails solely because valid provider-backed branch-policy evidence takes longer than the generic 10-second control timeout.
- Packed release certification no longer rejects the current CLI Canon `impl` group Help or root version presentation.
- Direct PR CLI tests no longer inherit an operator's Local Admission configuration.
- Governed Issue/PR mutation now detects provider-side target changes immediately before mutation instead of applying a decision to stale evidence.
- Artifact parsing no longer treats heading-like text inside fenced code as structural field boundaries.
- Schema-native materialization validates structured values against the governing schema before projection.
- v1 widget metadata is mapped into target-neutral presentation instead of leaking target-specific representation into Core.
- Task termination records are kept off the accepted source base and are projected through explicit termination authority rather than Source abort or Session close.
- Admission rechecks current task-termination evidence for issuance and already-issued task-bound Session requests.
- Local mTLS certification uses valid DER serial encoding.
- Dashboard dependency-guard tests are included in routine discovery exactly once.
- Dashboard verification build is serialized before package and Endpoint consumers use its output.
- Packed Local Execution Plane certification supplies exact absent-record Git evidence for task-termination checks.
- Release-preparation certification is no longer redundantly executed inside routine package verification.

## Behavioral changes

### CLI presentation and discovery

The standard public shell now uses CLI Canon 0.2 for root Help/version handling and the migrated command families. In particular:

- plain `inari --version` prints the package version only;
- `inari --version --json` is the CLI Canon package identity;
- `inari version --json` remains the Inari runtime/capability identity;
- group Help such as `inari impl --help` renders children relative to the selected group;
- Branch observation and Issue/PR View grammar/Help/typed dispatch are Canon-owned;
- the executable `setup` parent remains an explicitly bounded compatibility transition until CLI Canon can represent executable parents with child routes.

Scripts that parse the old human-readable root version or Help text must move to the canonical forms above. Automation that needs Inari runtime capabilities should use `inari version --json`, not root `--version --json`.

### Artifact contracts

Artifact Contract v2 is schema-native and uses a closed Draft 2020-12 root object schema plus direct-child RFC 6901 bindings. The v1 compatibility parser/serializer remains available. Effective caller input is derived from canonical bindings, and unsupported root constraints or unresolved projections fail closed rather than being approximated.

Governed artifact mutation is observation-bound. A target that changes between decision and effect is rejected and must be re-observed rather than silently patched.

### Publication and lifecycle authority

Pull-request publication is now explicitly classified by governed role: Implementation leaf, Source integration, Epic integration, or release. Task Session leaf PR authority is exact rather than inferred from broader historical publication bridges.

Implementation task termination is a distinct Runtime/operator-owned event. It is not equivalent to Source Change abort, Issue closure, or Session close. Admission uses fresh termination evidence at task-bound authorization boundaries.

### Local and remote authority

Local operator identity is defined by an enrolled Runtime-owned Ed25519 public key. Remote Repository Access Assertions bind verified subject, repository, App/installation, operation, target/input digest, issuer/audience/Relay, and bounded time evidence. These contracts are foundations for the still-open effectful grant/admission work listed below; this release does not claim those follow-up paths are complete.

## Upgrade instructions

Install the release:

```bash
npm install -g gh-inari@0.19.0
```

Verify package identity and the Inari runtime contract separately:

```bash
inari --version
inari --version --json
inari version --json
```

Existing supported Local Runtime configuration remains the upgrade base. CLI Canon now owns lexical config-path selection, but Inari retains component allowlisting, secure storage, ownership/mode, no-follow, and descriptor-relative checks.

For development use, start/resume the configured Local Runtime and create a fresh governed Session before Change/PR work. The branch-policy request used during Session startup now has the provider-control deadline required for normal GitHub latency.

## Breaking changes

This is a pre-1.0 minor release with intentional presentation/contract evolution.

- **Root version output changed under CLI Canon.** Consumers expecting `gh-inari <version>` from plain `--version` must accept the version-only form. Consumers expecting runtime capabilities from root `--version --json` must use named `version --json`.
- **CLI Help presentation is Canon-owned for migrated routes.** Consumers must not depend on legacy fully-qualified child strings inside group Help.
- **Artifact Contract v2 introduces schema-native semantics.** Existing v1 contracts remain supported, but new v2 consumers must obey direct-root binding and closed-schema rules.
- **Publication and task termination authority are more explicit and fail closed.** Automation relying on ambiguous role inference, stale governed observations, or treating Session/Source lifecycle events as task termination must use the canonical contracts.

No intentional removal is made to the supported ordinary Issue/PR governance path or existing supported Local Runtime setup state.
