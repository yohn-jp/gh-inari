# gh-inari 0.9.0

## Summary

0.9.0 hardens Inari's governed mutation and round-trip semantics after 0.8.0 and adds first-class Issue dependency semantics. The release makes `edit` the primary safe mutation path, governs title and Issue metadata more consistently, recovers common `gh`-style create intent into governed creation, and refreshes the packaged skill playbooks so direct governed creation is the canonical fast path.

## Highlights

- Safe governed mutation:
  - `edit` is the primary mutation path for explicit semantic or metadata changes.
  - `normalize` remains the preservation-oriented path for canonicalization when existing semantics can be proven.
  - `sync` remains the desired-state convergence path.
  - Unsupported draft Pull Request edits fail closed rather than being approximated.
- Governed create compatibility:
  - Common `gh`-compatible create options are recovered into governed creation instead of forcing callers through a raw-body escape hatch.
  - Title metadata is governed during creation rather than treated as an external side channel.
- First-class Issue dependency semantics:
  - Structured Issue envelopes can carry `dependencies.blockedBy` and `dependencies.blocks`.
  - Issue references use canonical repository identity and Issue number rather than owner/name text alone.
  - Malformed, duplicate, self-referential, and contradictory declarations are rejected deterministically.
  - Dependency semantics survive governed body round trips through bounded reserved metadata.
- Canonical skill workflows:
  - Direct governed Issue/PR creation is now the golden path when required fields are already known.
  - Schema inspection is conditional guidance rather than mandatory ceremony.
  - Validate/render remain explicit preview, debugging, and artifact-generation paths.
  - Inspect/repair playbooks now route through the current `check`, `get`, `explain`, `normalize`, `edit`, and `sync` model.

## Fixed

- Issue metadata round trips now verify the intended metadata after GitHub mutation.
- Omitted Issue sync fields remain omitted instead of being replaced unintentionally.
- Contract defaults are normalized before round-trip comparison.
- Defaulted fields no longer appear incorrectly in `missingFields`.
- Multi-select values enforce option round-trip invariants.
- Remediation rejects metadata that is not owned by the governed contract.
- Artifact round-trip diagnostics remain bounded.

## Behavioral changes

- Prefer `inari issue edit` / `inari pr edit` for explicit changes to an existing governed artifact.
- Use `normalize` only for semantics-preserving canonicalization; use `edit` or `sync` when the intended semantics or metadata are changing.
- Agents should use live `inari skill` output as the operational authority. The packaged static skill remains intentionally thin and does not duplicate leaf CLI syntax.
- Issue dependency declarations are now part of Inari's structured semantic model. Ordinary Markdown references are not inferred as dependency semantics.

## Upgrade instructions

Install the published package:

```bash
npm install --global gh-inari@0.9.0
inari --version
```

Existing successful 0.8 governed workflows remain supported. Callers can adopt direct governed creation and the updated edit/normalize/sync split incrementally.

## Breaking changes

No intentional breaking change to successful 0.8 governed Issue/PR workflows. 0.9.0 is a minor release because it adds Issue dependency semantics, new governed create compatibility behavior, and a clearer mutation contract.

## Operational guidance

Use Inari rather than raw `gh` for Issue, Pull Request, and template operations that Inari owns. For agent workflows, use `inari skill` to obtain the current bounded, versioned playbook instead of embedding a second copy of CLI workflow details.

Before publishing, the release commit must pass the repository CI, Governance, CodeQL, and package smoke-test gates described in `docs/releases/GOVERNANCE.md`.

## Known limitations

- The supported Node.js range remains `>=22.13`.
- GitHub-native Issue dependency state is not yet mutated or reconciled; 0.9.0 governs Inari's structured dependency semantics and bounded artifact representation.
- Free-form Markdown and natural-language semantic inference remain out of scope; unsupported or ambiguous representations fail closed.
- Repository identity is authoritative for dependency references; cross-host migration is treated as a distinct identity rather than inferred automatically.
- GitHub authentication and authorization remain supplied by the caller's environment.
