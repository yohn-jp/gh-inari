# gh-inari 0.17.0

## Summary

0.17.0 completes the Runtime component separation and setup convergence work that followed 0.16.0. Admission, Executor, Authority, setup application, CLI/console, and composition now have explicit ownership boundaries backed by public Runtime contracts and an import-boundary guard, while the packed CLI and real-browser setup path are certified end to end.

## Highlights

- **Runtime component separation**: Admission, Executor, Authority, setup application, CLI/console, and composition are separated behind explicit public ports and ownership rules.
- **Enforced dependency boundaries**: forbidden private-module imports are checked by the Runtime boundary guard as part of `pnpm run verify`.
- **Executor credential custody**: Issuer installation credentials and private-key reads remain confined to the Executor boundary; Admission and Agent paths stay provider-credential-free.
- **Canonical setup application**: CLI and browser share one secret-free setup state/action model with freshness, recovery, and owner-specific effects.
- **Governed Authority bootstrap**: first Runtime Authority publication, human merge/recheck, legacy migration, and partial-failure recovery are covered by packed certification.
- **Real-browser and local Runtime certification**: Chromium controls, file upload, refresh, dynamic ports, SSH forwarding, loopback/mTLS, denial paths, and alternate repository naming are exercised against the packed product.
- **Static onboarding descriptor**: the hosted onboarding descriptor is served as a static asset rather than requiring dynamic Worker handling.
- **Release certification isolation**: release-preparation certification is separated from routine repository verification and uses the dedicated `Release Certification <release-certification@yohn.jp>` identity.

## Fixed

- Initial setup can publish Runtime Authority trust when the protected ref has no existing Authority record.
- The setup console no longer overflows horizontally at a 360 px viewport.
- Release certification no longer needs to overwrite the repository's normal Git identity.
- Setup/provider fixture coverage now distinguishes bootstrap App-user authority from normal Executor installation authority.

## Behavioral changes

Internal Runtime responsibilities are now explicit and fail closed across component boundaries. The normal execution direction remains:

```text
CLI / Agent -> Admission -> Executor -> GitHub
```

Bootstrap setup uses operator App-user authority only for enrollment/publication operations; normal provider effects remain Executor-owned.

## Upgrade instructions

Upgrade the package normally:

```bash
npm install -g gh-inari@0.17.0
```

Existing supported local setup state is migrated through the canonical setup application. No manual JSON or key-file surgery is required.

## Breaking changes

None for the supported CLI/setup path. Internal module ownership and import boundaries are stricter; consumers relying on private source-module imports must use public package/runtime contracts instead.

## Known limitations

- Live GitHub/Cloudflare Hosted deployment is not established by the deterministic local certification suite.
- Platform-specific behavior not exercised by the release CI/runtime matrix remains unverified.
