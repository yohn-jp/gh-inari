# gh-inari 0.19.1

## Summary

0.19.1 is a patch release after 0.19.0 for Local Runtime Session lifecycle recovery and CLI output presentation. It contains the complete governed history from v0.19.0 through main at `002d26478c7b13cd87d1955b1da51aec75afe1ad` (3 commits).

## Highlights

- **Session lifecycle timeout**: provider-backed Session registration and closure now use the bounded provider-control deadline already used for branch-policy evidence.
- **Setup Runtime start handoff**: `inari setup` no longer dispatches Runtime start from the short-lived CLI and hands off to the canonical Runtime supervisor command.
- **Implementation operational output**: `inari impl validate` and `inari impl authorize` return compact operational output by default, with `--detail` for the full canonical projection.

## Fixed

- Local Admission client requests to `/v1/sessions` and `/v1/sessions/*` use the provider-control deadline instead of the default fast-control timeout, so Session registration and closure that depend on provider evidence no longer abort early (#1352).
- `inari setup next` on a `composition.start-runtime` action no longer attempts to start a long-running Runtime child from the short-lived CLI. It reports a `handoff` (human output, or JSON `kind: "handoff"` with the owner and command) naming `inari runtime supervise`, and exits 0 (#1354).
- `inari impl validate` and `inari impl authorize` separate operational status from full inspection evidence (#1355).

## Behavioral changes

- `inari impl validate` reports contract validity, current authorization state, and actionable violations by default, in terminal and JSON modes.
- `inari impl authorize` reports validity, authorization/current state, readiness classification, and actionable blockers by default, in terminal and JSON modes.
- Both commands accept `--detail` to include the full canonical projection, authorization record, base evidence, and readiness diagnostics. `inari impl show` and `inari impl inspect` remain the detailed inspection surfaces.
- The command contract version is `1.19.0` (`urn:inari:command-contract:1.19.0`). The `--detail` option help text now reads "Show full canonical, governed, and diagnostic evidence when supported."

## Upgrade instructions

Install the release:

```bash
npm install -g gh-inari@0.19.1
```

Existing 0.19.0 installs and Local Runtime configuration upgrade normally. Automation that parses the full output of `inari impl validate` or `inari impl authorize` must add `--detail`. Start the Runtime with the command reported by `inari setup`, `inari runtime supervise`.

## Breaking changes

None. The default output of `inari impl validate` and `inari impl authorize` is intentionally more compact; `--detail` restores the full evidence.

## Known limitations
